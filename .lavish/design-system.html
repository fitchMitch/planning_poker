Explication — système de conception

Oscar's Games

Charte visuelle pour un jeu sérieux de formation en entreprise : calme, lisible, pensé tablette. Source de référence : Artifact Claude, copiée dans ce dépôt sous app/assets/stylesheets/design_system/ et docs/design-system/.

Ce système donne 5 composants (Bouton, CarteQuiz, BarreProgression, Badge, RetourFeedback) bâtis sur un jeu de tokens unique, déjà intégré en CSS au dépôt — pas une proposition, un état existant.

Couleur

primary (sarcelle) porte l'action et la progression. accent (ambre) est réservé aux récompenses, pour garder son signal distinct. success/danger sont dédiés au retour sur les réponses, jamais réutilisés ailleurs. Contraste minimum 4,5:1 dans les deux thèmes.

Typographie

Une seule famille, Figtree. Titres en 600–700, texte courant en 400.

Titre XL.ds-heading-xl · 700 32/40
Titre LG.ds-heading-lg · 700 24/32
Titre MD.ds-heading-md · 600 18/26
Texte courant.ds-body · 400 16/24
Texte secondaire.ds-body-sm · 400 14/20
LIBELLÉ.ds-label · 600 13/18

Espacement & rayons

Échelle en incréments de 4px. Les rayons distinguent contrôles, cartes, panneaux et formes rondes.

Bouton

Une action principale par écran ; le reste en secondaire. .ds-btn, .ds-btn-primary, .ds-btn-secondary

Règles

  • Hauteur minimale 44px (cible tactile tablette).
  • Le focus clavier affiche toujours l'anneau focus-ring.
  • Le texte est un verbe d'action, jamais « OK » ou « Cliquez ici ».
  • Désactivé : jamais la seule action visible à l'écran.

Formulaire (nouveau, pas encore dans la charte)

Début de la partie formulaire : champ texte simple, sur le même gabarit que le bouton (hauteur 44px, bordure border, anneau focus-ring au clavier). À valider avant d'ajouter d'autres types de champs.

Adresse incomplète — vérifiez le domaine.

Règles proposées

  • Hauteur 44px minimum, comme .ds-btn, pour la cible tactile tablette — vaut aussi pour le menu select et la zone de clic de la case à cocher.
  • Bordure border au repos, anneau focus-ring au focus clavier, sur tous les champs y compris select et checkbox.
  • Champ invalide : bordure danger + message sous le champ, jamais la couleur seule.
  • Case à cocher : couleur de remplissage primary à l'état cochée, jamais accent (réservé aux récompenses).
  • Non confirmé : à faire valider puis ajouter aux tokens avant usage en production.

CarteQuiz

Question à choix multiple, le cœur de l'interaction pédagogique. Une seule question par carte, options en colonne.

Quelle action réduit un risque de non-conformité ?

Ignorer la procédure si elle ralentit le client
✓ Vérifier l'identité avant toute opération sensible
✕ Valider sans contrôle si le client est pressé

Règles

  • Repos : surface-200 + bordure border.
  • Sélectionnée avant validation : bordure primary.
  • Correcte : bordure/icône success. Incorrecte : danger, affichée uniquement sur l'option choisie.
  • Cible tactile ≥ 44px par option ; jamais de grille dense.

BarreProgression

Avancement dans un niveau ou un parcours, toujours accompagné d'un texte.

3 / 5 questions

Règles

  • Jamais la couleur seule — toujours un texte (« 3 / 5 » ou « 60 % »).
  • Remplissage primary, piste surface-300, coins radius-pill.
  • role="progressbar" avec les attributs aria-value*.

Badge

Jalon ou récompense débloqués. Garde le signal de récompense distinct de l'action courante.

🏆 5 bonnes réponses ⭐ Niveau conformité validé

Règles

  • Utilise accent, jamais primary.
  • Toujours un libellé court, jamais une icône seule.
  • Forme radius-pill.

RetourFeedback

Bandeau de confirmation juste après une réponse ou une action.

✓ Bonne réponse — vous avez bien identifié le risque.
✕ Pas tout à fait — relisez la section « Contrôle d'identité ».

Règles

  • Succès : success/on-success. Erreur : danger/on-danger, toujours avec une phrase qui explique pourquoi.
  • Près de l'élément concerné, jamais en popup bloquante pour une erreur récupérable.
  • Visible au moins 2 secondes avant de pouvoir être ignoré.

Ce qui est volontairement laissé de côté

  • Les classes CSS de CarteQuiz, BarreProgression, Badge et RetourFeedback sont définies ici pour la démonstration ; seuls .ds-btn, .ds-card et les styles de texte existent déjà dans components.css au dépôt.
  • Le ton éditorial (vocabulaire, pédagogie du feedback) est documenté dans le README mais non illustré ici — voir docs/design-system/README.md.
  • Toute évolution des tokens doit repartir de l'Artifact Claude, pas d'une édition manuelle de ces fichiers.
  • Le champ texte de la section Formulaire est une proposition pour cette revue, pas encore un composant validé dans la charte ni dans components.css.
